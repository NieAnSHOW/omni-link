## 核心论点（出现>=3次的观点）

### 1. "AI 能写代码之后，人的核心能力是设计 Harness（缰绳），而不是写代码本身"

- 来源: [Harness Engineering 橙皮书](https://www.huasheng.ai/orange-books/harness/) - 可信度: 一手
- 来源: [Claude Code 源码解析文章](https://www.aixq.cc/19055.html) - 可信度: 一手
- 来源: [Claude Code 源码解析橙皮书](https://github.com/alchaincyf/claude-code-source-analysis-orange-book) - 可信度: 一手
- 来源: [Claude Code Skills 深度调研](https://www.huasheng.ai/insights/claude-code-skills-guide/) - 可信度: 一手

**展开**: Harness 是把模型能力变成稳定执行能力的工程化装置。它要解决的不是"模型会不会答"，而是"模型能不能在真实环境里持续、稳定、可验证地把事做完"。Claude Code 60% 是模型能力，40% 是 Harness Engineering。

### 2. "代码杠杆 + 媒体杠杆 = AI 时代一人公司的核心公式"

- 来源: [播客：代码杠杆+媒体杠杆](https://www.xiaoyuzhoufm.com/episode/67507ce7fcfd398727dac008) - 可信度: 一手（花叔口述）
- 来源: [虎嗅转载：纳瓦尔的四种杠杆](https://www.huxiu.com/article/3762296.html) - 可信度: 二手（AI产品黄叔整理，花叔口述）
- 来源: [花叔个人主页](https://huasheng.ai/) - 可信度: 一手
- 来源: [腾讯直播访谈](http://m.blog.itpub.net/70043119/viewspace-3063412/) - 可信度: 一手

**展开**: 引用 Naval 的四种杠杆（金钱、人力、媒体、代码）。以前代码杠杆被程序员"垄断"，AI 编程让普通人也能用上。代码杠杆和媒体杠杆结合是最优解——产品再好也得有人知道。

### 3. "先完成再完美（先做 20 个垃圾出来）"

- 来源: [播客：提钱退休](https://www.xiaoyuzhoufm.com/episode/674c70c80ed328720ab192a0) - 可信度: 一手
- 来源: [播客：三五环](https://www.xiaoyuzhoufm.com/episode/6757028917cd5416adbdf24f) - 可信度: 一手

**展开**: 不要追求完美，先做出来。做出来的过程本身就是练习和积累。只有做出来才有机会被看到，才有可能变现。Cursor 开发的唯一诀窍就是"先做出来"。

### 4. "Build in Public：产品是和用户共建出来的"

- 来源: [虎嗅：纳瓦尔的四种杠杆](https://www.huxiu.com/article/3762296.html) - 可信度: 二手（整理自花叔口述）

**展开**: 小猫补光灯 Pro 版本是"用户逼出来的"。传统 Build in Public 是积累种子用户，花叔的版本是深度用户共创——从需求到功能全部和用户一起完成。从哪里获得需求就发到哪里（小红书需求 -> 小红书运营）。

## 自创术语/概念

### 1. Harness Engineering（驾驭工程/缰绳工程）
- **解释**: 在大模型和终端用户之间设计、实现、优化工程层的方法论。Harness 不是某个新组件，而是把模型能力变成稳定执行能力的那套工程化装置。核心组件：指令层、约束层、能力层、记忆层、编排层。
- **来源**: [Harness Engineering 橙皮书](https://www.huasheng.ai/orange-books/harness/) | [Claude Code 源码解析](https://www.aixq.cc/19055.html) | 可信度: 一手

### 2. 橙皮书（Orange Book）
- **解释**: 花叔的系统性 AI 编程学习资料的命名体系，目前 7+ 本：Claude Code 从入门到精通、Claude Code 源码解析、Harness Engineering、Agent Skills、OpenClaw、Hermes Agent、Cursor 从入门到精通等。特点是全部免费，来自一手实践。
- **来源**: [AI编程橙皮书页面](https://www.huasheng.ai/orange-books/) | 可信度: 一手

### 3. AI Native Coder
- **解释**: 花叔给自己的标签。指不需要传统编程能力，完全通过 AI 工具实现产品开发的人。花叔从未手写一行代码，却做出了 App Store #1 产品、7 本技术书、30万+ 粉丝内容运营。
- **来源**: [花叔个人主页](https://huasheng.ai/) | [GitHub README](https://github.com/alchaincyf/claude-code-orange-book) | 可信度: 一手

### 4. SPACE 模型
- **解释**: 评估一人公司适合度的 5 维框架：Skills（技能）、Passion（激情）、Adaptability（适应性）、Connection（连接）、Endurance（耐力）。
- **来源**: [腾讯直播访谈](http://m.blog.itpub.net/70043119/viewspace-3063412/) | 可信度: 一手

### 5. 女娲.skill（Nuwa Skill）
- **解释**: 蒸馏任何人思维方式的 Claude Code Skill。6个 Agent 并行调研（著作、访谈、决策记录、社交媒体等），5阶段蒸馏流水线，输出可运行的人物认知框架 Skill。命名来自中国神话女娲造人。
- **来源**: [nuwa-skill GitHub](https://github.com/alchaincyf/nuwa-skill) | 可信度: 一手

### 6. 达尔文.skill（Darwin Skill）
- **解释**: 让所有 Skill 持续进化的系统。受 Karpathy autoresearch 启发，用自主实验循环批量优化所有 Skill：8维度评估、棘轮机制（只保留改进，自动回滚退步）、独立子agent评分。
- **来源**: [nuwa-skill README](https://github.com/alchaincyf/nuwa-skill) | 可信度: 一手

### 7. 蜂群模式（Agent Swarm）
- **解释**: 受 Nicholas Carlini 用 16 个 Claude 实例自主构建 C 编译器启发。多个 Agent 并行协作，没有 master，纯 git 自组织。用 tmux + git worktree 实现 Agent 隔离。
- **来源**: [huashu-skills README](https://github.com/alchaincyf/huashu-skills) | 可信度: 一手

### 8. 三遍审校降AI味
- **解释**: 系统化降低 AI 检测率至 30% 以下的方法：第一遍内容审校（事实核查、逻辑链），第二遍 6 大类 AI 腔识别与改写（套话、句式、词汇、结构、态度、细节缺失），第三遍节奏打磨。
- **来源**: [huashu-skills README](https://github.com/alchaincyf/huashu-skills) | 可信度: 一手

### 9. "你想蒸馏的下一个员工，何必是同事"
- **解释**: 女娲.skill 的口号。同事.skill 证明蒸馏人是可行的，但不必只蒸馏身边的同事——去蒸馏各领域最强的人。
- **来源**: [nuwa-skill GitHub](https://github.com/alchaincyf/nuwa-skill) | 可信度: 一手
